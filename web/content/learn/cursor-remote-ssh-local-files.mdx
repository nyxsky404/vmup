Cursor’s remote agent cannot open a laptop path that was only attached as a local reference. Copy the file into the remote workspace, then attach or mention the remote path.

*This is the filesystem boundary behind the Cursor failure: before upload the remote file is missing; after upload it is a valid PNG.*

## Why Cursor cannot access the local file

In a Remote-SSH window, Cursor’s tools run against the remote workspace. A path such as `C:\Users\you\Desktop\bug.png` or `/Users/you/Desktop/bug.png` describes the laptop filesystem, not the server filesystem.

A Cursor staff response confirms this behavior in a [Remote-SSH local-document report](https://forum.cursor.com/t/cursor-cannot-analyze-local-documents-when-connected-via-ssh-files-must-be-uploaded-to-the-remote-server/168451): supported formats can be uploaded by content, but a local path reference cannot be resolved by the remote agent. Cursor’s documentation also explains how to add files already available to the workspace with [`@Files`](https://docs.cursor.com/context/%40-symbols/%40-files).

## Upload the file with scp

The free manual solution is to copy the file into the remote workspace. Run [`scp`](https://man.openbsd.org/scp.1) from the laptop.

### macOS or Linux

```bash
scp ~/Desktop/bug.png user@server:~/project/bug.png
```

**Expected result:** `bug.png` appears inside the remote project.

### Windows through WSL

```bash
scp /mnt/c/Users/you/Desktop/bug.png user@server:~/project/bug.png
```

The `/mnt/c` form follows Microsoft’s documented [WSL filesystem mapping](https://learn.microsoft.com/en-us/windows/wsl/filesystems).

**Expected result:** the Windows file is copied from the WSL-visible path into `~/project/bug.png` on the server.

### Confirm it from the remote window

```bash
ls -lh ~/project/bug.png
```

**Expected result:** the integrated terminal prints the remote file and a non-zero size.

In Cursor chat, attach `@bug.png` or describe `~/project/bug.png`.

**Expected result:** the attachment resolves to a path inside the remote workspace, and the agent can read it.

## Stop uploading files one at a time

`scp` remains the right baseline for one named file. When the task includes several screenshots, a PDF and a recording, [install vmup](/docs/install), complete the [first SSH upload](/docs/quickstart), and send the set as one remote folder:

```bash
vmup ./bug.png ./notes.pdf ./recording.mov
```

**Expected result:** vmup prints one `Agent folder:` path; paste the generated prompt into the Cursor thread already connected to the host.

## Drag into the remote Explorer

If the file is already saved, drag it from the desktop into Cursor’s Remote-SSH Explorer. Cursor documents [dragging workspace files into Agent as context](https://docs.cursor.com/context/%40-symbols/%40-files-and-folders); first make sure the file appears in the remote Explorer rather than only as a laptop attachment.

**Expected result:** the file becomes visible in the remote project tree and can be selected with `@Files`.

## Common failures

- **The attachment chip shows `C:\Users\…`:** the remote agent received a local path. Upload the file first.
- **`scp` reports permission denied:** copy into a directory owned by the SSH user, such as the project or home directory.
- **The file is on WSL but the agent is on another server:** use `scp`; `/mnt/c/…` only exists inside the local WSL environment.
- **The file uploaded outside the project:** use the absolute remote path, or move it into the remote workspace before using `@Files`.

For mixed files, read [send files to a remote coding agent](/learn/send-files-to-remote-coding-agent). For the same filesystem boundary in a terminal agent, see [paste an image into Claude Code over SSH](/learn/claude-code-paste-image-ssh).

## Quick answers

**Why can’t Cursor analyze a local file over Remote-SSH?**
The agent runs against the remote workspace. A local Windows or macOS path is not a file path on that server.

**Do any attachments work over Cursor Remote-SSH?**
Some supported formats are uploaded by content. If the attachment remains a local path, copy it into the remote workspace before asking the agent to read it.

**How do I give Cursor a screenshot on a remote VM?**
Upload the PNG with `scp`, drag it into the remote Explorer, or send a batch, then reference the remote file.

**What should I check before using @Files?**
Confirm the file appears in the remote Explorer or can be listed from the remote integrated terminal.
