“No image found in clipboard” means Claude Code did not receive usable image data from the clipboard available to the remote process. Save the screenshot as a file, transfer it to the server, and reference that remote path instead.

## What the error means over SSH

Your terminal is on the laptop, but Claude Code is running on the server. A screenshot may exist in the laptop clipboard while the remote Linux session has no image-capable clipboard, no display server, or a terminal path that does not return the image bytes Claude Code expects.

Anthropic tracks both a [Claude Code 2.1.181 image-paste regression over SSH](https://github.com/anthropics/claude-code/issues/69330) and the broader [headless Linux clipboard limitation](https://github.com/anthropics/claude-code/issues/42712). Those reports are stronger evidence than assuming every terminal behaves the same way.

## Check whether the file is remote

```bash
hostname
pwd
test -f /tmp/bug.png && echo found || echo missing
```

**Expected result:** `hostname` identifies the server and the final line prints `missing` until you upload the image.

If the prompt contains `/Users/you/…` or `C:\Users\you\…`, it still contains a laptop path. The server cannot open it.

## Fix the error with scp

Run the upload from the laptop. [`scp` copies a local source to a remote target over SSH](https://man.openbsd.org/scp.1).

### macOS or Linux

```bash
scp ~/Desktop/bug.png user@server:/tmp/bug.png
```

**Expected result:** the command exits without an error.

### Windows through WSL

```bash
scp /mnt/c/Users/you/Pictures/bug.png user@server:/tmp/bug.png
```

Microsoft documents that the Windows `C:` drive appears in WSL under [`/mnt/c`](https://learn.microsoft.com/en-us/windows/wsl/filesystems).

**Expected result:** `/tmp/bug.png` exists on the remote Linux host.

### Verify and give Claude the path

```bash
ssh user@server 'file /tmp/bug.png'
```

**Expected result:** the server reports PNG or other supported image data.

```text
Inspect /tmp/bug.png and explain the visible error.
```

**Expected result:** Claude Code reads the remote file; it no longer needs the image clipboard for this request.

## Send repeated screenshots without rebuilding the command

`scp` is still the clearest manual fix for one screenshot. For repeated screenshots or a mixed batch, [install vmup](/docs/install) and complete the [first SSH upload](/docs/quickstart), then collect clipboard images into one remote folder:

```bash
vmup --clip
```

**Expected result:** vmup prints an `Agent folder:` path and copies a prompt that points Claude Code at that folder.

## tmux and WSL checks

- **tmux:** first verify that ordinary text paste reaches the prompt. Regardless of the keybinding, a remote file path continues to work.
- **WSL without a second SSH hop:** Windows screenshots normally live under `/mnt/c/Users/…`. Give Claude Code that WSL path after saving the image.
- **WSL followed by SSH:** `/mnt/c/…` belongs to the local WSL environment, not the second server. Run `scp` again to place the image on that server.
- **Ctrl+V does nothing:** the terminal may consume the key before Claude Code sees it. Type or paste the remote path as ordinary text.

For the complete upload workflow, read [how to paste an image into Claude Code over SSH](/learn/claude-code-paste-image-ssh). For helper and shim trade-offs, see [Claude Code SSH screenshot tools compared](/learn/claude-code-ssh-screenshot-tools).

## Quick answers

**What does “No image found in clipboard” mean in Claude Code over SSH?**
Claude Code did not receive usable image data from the clipboard available to the remote process. The screenshot may still exist only on the laptop.

**Is this the same as Ctrl+V doing nothing?**
The underlying boundary may be the same, but the visible behavior depends on the terminal and Claude Code version. Some sessions print the error; others receive no image paste event.

**Does this error also happen locally?**
Yes. A local clipboard can contain text, a file reference, or an image format Claude Code does not accept.

**How do I fix it without a clipboard daemon?**
Save the image, upload it with `scp`, and put the remote path in the prompt.
